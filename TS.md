# Техническое задание: личный трекер задач (MVP)

## 1. Цель и принципы продукта

Создать простой одностраничный веб-трекер для личных задач. Продукт должен помогать быстро записывать дела, видеть просроченные и ближайшие задачи и отмечать выполнение — без проектов, досок, тегов и обязательной регистрации.

Ключевые принципы:

- Быстрое добавление задачи с минимумом обязательных полей.
- Понятное разделение задач по срокам, включая задачи без срока.
- Аккуратный современный интерфейс, удобный на телефоне и компьютере.
- Данные хранятся локально на устройстве пользователя; облачная синхронизация не входит в MVP.
- Цвет никогда не является единственным способом передать статус, приоритет или просрочку.

## 2. Пользователь и доступ

- Один пользователь — владелец задач.
- Регистрация и авторизация не требуются.
- Приложение доступно через современный браузер. Для системных уведомлений требуется поддержка браузером Notifications API и защищённое соединение (HTTPS или localhost).
- Данные не отправляются на сервер и не синхронизируются между устройствами.

## 3. Модель данных

| Поле | Тип | Обязательность и правила |
|---|---|---|
| `id` | UUID | Обязательное, генерируется автоматически |
| `title` | string | Обязательное, после удаления пробелов не пустое, максимум 200 символов |
| `description` | string | Необязательное |
| `dueDate` | date `YYYY-MM-DD` или `null` | Необязательное. `null` означает «Без срока» |
| `priority` | `high` / `medium` / `low` | Обязательное, по умолчанию `medium` |
| `status` | `todo` / `done` | Обязательное, по умолчанию `todo` |
| `createdAt` | datetime ISO 8601 | Обязательное, устанавливается при создании и не меняется |
| `completedAt` | datetime ISO 8601 или `null` | Устанавливается при завершении; очищается при возврате в работу |

`isOverdue` не хранится в данных, а вычисляется при отображении: `status = todo AND dueDate < сегодняшняя локальная дата устройства`.

Дата без времени трактуется как календарная дата в часовом поясе устройства. Сравнение дат не должно сдвигать срок из-за преобразования `YYYY-MM-DD` в UTC.

## 4. Структура главного экрана

### Основная навигация

Три раздела:

1. **Сегодня** — отдельный блок просроченных задач, задачи на сегодня и задачи без срока.
2. **Предстоящие** — незавершённые задачи со сроком позже сегодняшней локальной даты.
3. **Завершённые** — выполненные задачи, недавно завершённые отображаются первыми.

На разделах можно показывать счётчики. На «Сегодня» счётчик просроченных задач должен быть отдельным и явно подписанным, например «Просрочено · 3», а не только обозначенным цветом.

### «Сегодня»

Внутри раздела показывать группы в следующем порядке:

1. **Просрочено** — задачи с прошедшим сроком. Группа визуально отделена от задач на сегодня.
2. **На сегодня** — задачи со сроком, равным сегодняшней дате.
3. **Без срока** — задачи без срока.

Если группа пуста, не показывать пустой заголовок группы. Если все три группы пусты, показать состояние «На сегодня задач нет» и действие «Добавить задачу».

### «Предстоящие»

Показывать только незавершённые задачи с будущим сроком. Пустое состояние: «Предстоящих задач нет» с действиями «Добавить задачу» и «Открыть задачи без срока» (переход в раздел «Сегодня» к группе «Без срока»).

### «Завершённые»

Пустое состояние: **«Нет завершённых задач»** с понятными действиями «Добавить задачу» и «К задачам на сегодня».

## 5. Функциональные требования

### 5.1 Создание и быстрый ввод

- Задачу можно создать через короткое поле быстрого добавления или полную форму.
- В быстром вводе обязательны только название и действие «Добавить».
- Срок необязателен. Для кратчайшего сценария задача без указанного срока создаётся без срока.
- При создании по Enter задача сохраняется; поле остаётся готовым к следующему вводу и получает фокус.
- Значения по умолчанию: `priority = medium`, `status = todo`.
- После создания задача появляется в соответствующей группе без перезагрузки страницы.
- Для новой задачи со сроком допускается только сегодняшняя или будущая дата. Просроченный срок можно назначить существующей задаче при редактировании.

### 5.2 Просмотр и редактирование

- Нажатие на карточку открывает форму редактирования, но не меняет статус.
- Переключение выполнения выполняется отдельным чекбоксом или кнопкой с доступным названием.
- В форме редактируются название, описание, срок и приоритет.
- Срок можно добавить, изменить или убрать у любой задачи, в том числе у просроченной.
- Изменения сохраняются только после явного нажатия «Сохранить». Закрытие формы с несохранёнными изменениями вызывает понятное предупреждение.
- После изменения срока или статуса задача сразу перемещается в соответствующую группу.

### 5.3 Завершение и повторное открытие

- Отметка задачи выполненной устанавливает `status = done` и `completedAt = текущее время устройства`.
- Повторное открытие задачи устанавливает `status = todo` и очищает `completedAt`.
- При повторном завершении записывается новое время завершения.
- Удаление требует подтверждения. После удаления доступно кратковременное действие «Отменить» (toast/snackbar), если это не усложняет реализацию.

### 5.4 Сортировка

При равных основных условиях раньше показываются задачи, созданные раньше (`createdAt` по возрастанию). Порядок всегда детерминирован.

- **Просрочено:** более ранний срок выше; при одинаковом сроке — приоритет `high → medium → low`, затем более ранний `createdAt`.
- **На сегодня:** приоритет `high → medium → low`, затем более ранний `createdAt`.
- **Без срока:** приоритет `high → medium → low`, затем более ранний `createdAt`.
- **Предстоящие:** более ранний срок выше; при одинаковом сроке — приоритет `high → medium → low`, затем более ранний `createdAt`.
- **Завершённые:** `completedAt` по убыванию (последние завершённые сверху); при одинаковом времени — более ранний `createdAt`.

### 5.5 Приоритет, статус и просрочка

Приоритеты:

- Высокий — красный цвет и текст/значок «Высокий».
- Средний — жёлтый цвет и текст/значок «Средний».
- Низкий — зелёный цвет и текст/значок «Низкий».

Просроченная задача имеет заметную, но не мешающую чтению маркировку: текст «Просрочено на N дн.» и/или значок с доступным текстовым названием. Не использовать один только красный цвет или изменение жирности текста.

## 6. Уведомления

- Уведомления показываются только при открытии приложения; фоновые push-уведомления и доставка при закрытом приложении не входят в MVP.
- При каждом новом открытии приложения формируется сводка: количество просроченных задач и задач со сроком на сегодня. Если задач нет, уведомление не показывается.
- На одном устройстве при одновременном открытии нескольких вкладок уведомление показывает только одна вкладка; остальные вкладки не создают дубликаты.
- При переключении на уже открытую вкладку повторное уведомление не показывается. Новым открытием считается новая загрузка приложения после закрытия/перезагрузки.
- Время и календарная дата определяются по настройкам времени и часовому поясу устройства пользователя.
- Запрашивать системное разрешение только в контексте понятного действия/настройки уведомлений, а не неожиданно при первом запуске. Пользователь может отключить уведомления.
- При запрете разрешения или отсутствии поддержки системных уведомлений приложение продолжает работать; вместо системного уведомления можно показать сводку внутри интерфейса.
- Звук не воспроизводится.

## 7. Хранение и резервное копирование

- Основное хранилище — `localStorage` браузера.
- Состояние загружается при запуске и сохраняется после каждого успешного изменения данных.
- Изменения синхронизируются между вкладками одного браузерного профиля; интерфейс другой вкладки обновляется без перезагрузки.
- В настройках доступны:
  - **Экспорт** всех задач в файл JSON с версией формата и временем создания резервной копии.
  - **Импорт** ранее экспортированного JSON-файла.
- Перед импортом показать количество задач и запросить подтверждение. Импорт заменяет текущий список задач целиком; сообщить об этом до подтверждения. Некорректный файл не должен менять существующие данные.
- Если данные повреждены или браузерное хранилище недоступно/переполнено, показать понятное сообщение и предложить экспорт/импорт или повторить действие. Не очищать данные и не подменять ошибку пустым списком молча.
- В интерфейсе или справке пояснить: очистка данных сайта/браузера может удалить задачи; резервная копия хранится там, куда её скачал пользователь.

## 8. Визуальный дизайн и доступность

- Современный, привлекательный и спокойный визуальный стиль; приоритет — читаемость и быстрое сканирование списка, а не декоративные эффекты.
- Чёткая визуальная иерархия: заголовок раздела, счётчики, группы по срокам, карточки и основное действие добавления.
- Карточка показывает название, срок или «Без срока», приоритет и состояние выполнения.
- Использовать понятные подписи действий, видимые состояния hover/focus/active, достаточный контраст текста и фона.
- Цвет не единственный индикатор: приоритеты, завершение и просрочка дополнительно обозначаются текстом, значком или формой.
- Все интерактивные элементы доступны с клавиатуры; у полей есть подписи, у иконок-кнопок — accessible name.
- Диалог редактирования закрывается предсказуемо, фокус не теряется; ошибки формы показаны рядом с полем и доступны вспомогательным технологиям.
- Пустые состояния содержат короткое объяснение и полезное следующее действие.
- Адаптивность:
  - Desktop: от 1200 px.
  - Tablet: 768–1199 px.
  - Mobile: до 767 px.
- На мобильном экране основные действия доступны без горизонтальной прокрутки; элементы управления удобны для касания.

## 9. Валидация и обработка ошибок

- `title` обязателен, после удаления пробелов не пустой, максимум 200 символов.
- `description` необязателен.
- `dueDate` необязателен. Если указан при создании — сегодня или более поздняя дата; при редактировании можно установить любой новый срок, в том числе уже прошедший.
- Невалидная форма не сохраняется; сообщение объясняет, что исправить.
- При импорте проверяются версия формата, структура, обязательные поля, типы и допустимые значения enum.
- Ошибки чтения/записи локального хранилища и экспорта/импорта отображаются пользователю явно.

## 10. Технические требования

- SPA, компонентная архитектура, TypeScript.
- React или Vue; сборка Vite.
- Централизованное управление состоянием (например, Zustand/Pinia) либо другой простой подход, соответствующий масштабу MVP.
- Хранение в `localStorage`; не использовать серверную БД и облачный аккаунт.
- Системные уведомления — Notifications API при открытом приложении; механизм предотвращения дубликатов между вкладками (например, Web Locks API с безопасным fallback).
- Корректная работа на актуальных версиях основных браузеров. При неподдерживаемой функции — понятное fallback-поведение.

## 11. Критерии приёмки (Definition of Done)

- [ ] Можно создать задачу только с названием — она появляется в группе «Без срока».
- [ ] Можно создать задачу со сроком на сегодня или в будущем; нельзя создать задачу с прошедшим сроком.
- [ ] Существующей задаче можно добавить, изменить или удалить срок, включая изменение срока просроченной задачи.
- [ ] Нажатие на карточку открывает редактирование; только отдельный контрол меняет статус.
- [ ] Можно редактировать и удалять задачу; при удалении показано подтверждение.
- [ ] При завершении заполняется `completedAt`; при повторном открытии он очищается.
- [ ] Раздел «Сегодня» показывает отдельные группы «Просрочено», «На сегодня», «Без срока» именно в этом порядке.
- [ ] Раздел «Предстоящие» показывает задачи со сроком позже сегодняшней даты устройства.
- [ ] Раздел «Завершённые» сортирует задачи по `completedAt`, последние завершённые — сверху.
- [ ] Сортировка во всех группах стабильна; при равных условиях раньше созданная задача выше.
- [ ] Просрочка и приоритет распознаются не только по цвету.
- [ ] Пустое состояние завершённых задач содержит текст «Нет завершённых задач» и действия добавления/перехода.
- [ ] После обновления страницы задачи сохраняются; изменение в другой вкладке синхронизируется.
- [ ] Экспорт создаёт резервный JSON; импорт показывает предупреждение о замене, подтверждение и не повреждает данные при ошибке.
- [ ] Уведомление формируется при новом открытии приложения по времени устройства, но не дублируется во второй открытой вкладке.
- [ ] При отказе от уведомлений, недоступности Notification API или ошибке хранилища приложение остаётся работоспособным и показывает понятное сообщение/fallback.
- [ ] Интерфейс адаптивен, доступен с клавиатуры и имеет проверяемые состояния фокуса и контраста.

## 12. Этапы и оценка сроков

## 13. Зафиксированные решения для генерации и приёмки

Раздел дополняет ТЗ и фиксирует решения, которые нельзя оставлять на усмотрение генератора. **При противоречии с предыдущими разделами приоритет имеет этот раздел.** Все пункты проверяются в приёмке.

### 13.1. Стек и архитектура

- React 19 + TypeScript + Vite 8 + Zustand 5.
- Обычный CSS без UI-библиотек; системный шрифт; никаких внешних CDN, шрифтов, аналитики и сетевых запросов.
- SPA без роутера: разделы переключаются состоянием. Бэкенд, аккаунты и облако не используются.
- Данные — `localStorage`; состояние сохраняется после каждого успешного изменения.
- Сборка через npm: `npm run dev`, `npm run build`, `npm run preview`. Целевая версия Node — 20.19+ (проверено на 24.22).
- Даты хранятся как `YYYY-MM-DD` (локальная календарная дата) и ISO 8601 для `createdAt`/`completedAt`. Запрещено получать локальную дату через `toISOString()` и парсить `YYYY-MM-DD` через `new Date('YYYY-MM-DD')` — только `new Date(y, m-1, d)`.

### 13.2. Быстрый ввод, создание и редактирование

- Быстрое поле содержит **только название**. Enter создаёт задачу `status = todo`, `priority = medium`, `dueDate = null`, очищает поле и возвращает фокус.
- Полная форма открывается действием «Подробнее: срок, приоритет и описание» и позволяет задать название, описание, срок и приоритет.
- Название: после `trim()` не пустое, максимум 200 символов. Пустое/пробельное название не сохраняется, ошибка показывается рядом с полем.
- Новая задача со сроком: только сегодня или будущая дата. Редактирование существующей задачи допускает любую дату, включая прошедшую, а также удаление срока.
- После создания приложение переходит в раздел, где задача видна: без срока/сегодня/просрочено → «Сегодня», будущий срок → «Предстоящие». Новая карточка подсвечивается.
- Нажатие на карточку открывает редактирование. Статус меняет только отдельный чекбокс/кнопка с доступным названием.
- Изменения сохраняются только по кнопке «Сохранить». Закрытие с несохранёнными изменениями показывает предупреждение с выбором «Продолжить редактирование» / «Закрыть без сохранения».
- Удаление требует подтверждения. После удаления показывается toast с действием «Отменить» на 6 секунд.
- Завершение выставляет `completedAt = текущее время устройства`; повторное открытие очищает `completedAt`; повторное завершение записывает новое время.

### 13.3. Разделы и счётчики

- «Сегодня»: группы строго в порядке **«Просрочено» → «На сегодня» → «Без срока»**. Пустые группы не показываются.
- На «Сегодня» счётчик просроченных задач — отдельная явно подписанная кнопка/плашка **«Просрочено · N»**. Он не заменяется цветом или точкой.
- Если все три группы пусты: заголовок **«На сегодня задач нет»**, пояснение и действие **«Добавить задачу»**; дополнительно допускается «Создать со сроком».
- «Предстоящие»: только незавершённые задачи с `dueDate > сегодня`. Пустое состояние: **«Предстоящих задач нет»**, действия **«Добавить задачу»** и **«Открыть задачи без срока»** (переход в «Сегодня» к группе «Без срока»).
- «Завершённые»: только `status = done`, сортировка по `completedAt` по убыванию. Пустое состояние: **«Нет завершённых задач»**, действия **«Добавить задачу»** и **«К задачам на сегодня»**.
- Счётчики показываются на всех трёх разделах. Внутри «Сегодня» у каждой группы свой счётчик. Цвет не является единственным носителем статуса.

### 13.4. Сортировка

- **Просрочено:** `dueDate` по возрастанию → приоритет `high → medium → low` → `createdAt` по возрастанию → `id`.
- **На сегодня:** приоритет → `createdAt` → `id`.
- **Без срока:** приоритет → `createdAt` → `id`.
- **Предстоящие:** `dueDate` → приоритет → `createdAt` → `id`.
- **Завершённые:** `completedAt` по убыванию → `createdAt` по возрастанию → `id`.
- `id` — обязательный финальный tie-breaker, потому что `createdAt` может совпасть до миллисекунды. Порядок всегда детерминирован.

### 13.5. Даты, время и просрочка

- «Сегодня» определяется по локальной дате устройства, а не по UTC.
- `isOverdue = status = todo AND dueDate < сегодняшняя локальная дата`.
- «Просрочено на N дн.»: N — разница в календарных днях (сегодня минус `dueDate`), без влияния перехода на летнее время. Используется корректное склонение: день / дня / дней.
- Зависимые от даты группы, счётчики и просрочка пересчитываются при возврате фокуса/видимости вкладки, при действиях и не реже раза в 30 секунд; переход через полночь не должен оставлять вчерашнюю картину.
- `createdAt` и `completedAt` — ISO 8601; для сортировки допустимо лексикографическое сравнение. Отображение — в локальном времени устройства.

### 13.6. Уведомления

- При каждой загрузке приложения (новое открытие/перезагрузка) формируется сводка: количество просроченных и количество задач на сегодня.
- **Сводка внутри интерфейса** показывается всегда, если `просрочено + на сегодня > 0`, независимо от системного разрешения. Её можно скрыть. Если задач нет — сводка не показывается.
- **Системные уведомления** показываются только если:
  1) браузер поддерживает Notifications API;
  2) разрешение `granted`;
  3) пользователь включил тумблер «Системные уведомления» в настройках.
- По умолчанию системные уведомления **выключены**. Разрешение запрашивается только по клику на тумблер в настройках, не при первом запуске.
- При `default`/`denied`/`unsupported`/выключенном тумблере приложение продолжает работать, повторные запросы не показываются; используется сводка в интерфейсе. При `denied` в настройках есть пояснение, как разрешить уведомления, и кнопка «Проверить разрешение».
- Одна системная сводка на загрузку. При одновременной загрузке нескольких вкладок уведомление показывает только одна: Web Locks + отметка `lastNotifiedAt` в `localStorage`; дубли в окне 5 секунд подавляются. Fallback без Web Locks — отметка в `localStorage` + короткая задержка и повторная проверка.
- Переключение на уже открытую вкладку не показывает уведомление повторно. Новая загрузка после закрытия/перезагрузки считается новым открытием.
- Текст: заголовок «Задачи на сегодня», тело «Просрочено: N · На сегодня: M» (нулевые части опускаются). `silent: true`, `tag: 'today-summary'`. Клик фокусирует приложение и открывает «Сегодня».
- Уведомления только при открытом приложении; push, service worker и доставка при закрытом приложении не входят в MVP. Звук не воспроизводится.
- Ограничения: в обычной вкладке iOS Safari системных уведомлений нет — только in-app сводка; по LAN-адресу `http://192.168...` нет secure context. Проверка системных уведомлений — в Chrome/Safari на `localhost` или HTTPS.
- Настройка хранится в `tracker.settings.v1`.

### 13.7. Хранение, экспорт и импорт

- Ключи: `tracker.tasks.v1`, `tracker.settings.v1`, `tracker.lastNotifiedAt.v1`.
- Формат задач в хранилище: `{ "version": 1, "updatedAt": "ISO", "tasks": [...] }`.
- Сохранение после каждого успешного изменения. Синхронизация вкладок — через событие `storage`; интерфейс обновляется без перезагрузки. При конфликте действует last-write-wins; открытая форма редактирования не перезаписывается до сохранения.
- Экспорт — JSON-файл `tasks-backup-YYYY-MM-DD.json`:
  ```json
  {
    "app": "personal-task-tracker",
    "version": 1,
    "exportedAt": "2026-11-03T15:00:00.000Z",
    "tasks": []
  }
  ```
- Импорт: максимум 5 МБ; проверяются версия формата, наличие массива `tasks`, обязательные поля, типы, enum-значения, реальность дат `YYYY-MM-DD`, ISO у `createdAt`/`completedAt`, уникальность UUID и согласованность `status = done ⇔ completedAt != null`.
- Перед импортом показывается число задач в файле и текущее число задач, предупреждение о полной замене и подтверждение. Импорт заменяет только задачи; настройки не меняются. Невалидный файл не меняет существующие данные.
- Повреждённый JSON/схема: блокирующий экран «Не удалось прочитать задачи» с действиями «Повторить чтение», «Скачать повреждённые данные», «Импортировать резервную копию», «Сбросить данные» (с подтверждением). Молчаливая замена пустым списком запрещена.
- Переполнение/недоступность `localStorage`: приложение остаётся работоспособным в памяти, показывает постоянный баннер «Не сохранено» с действиями «Повторить» и «Скачать копию». Данные не теряются молча.
- В интерфейсе/настройках есть предупреждение: очистка данных сайта может удалить задачи; резервная копия хранится там, куда её скачали.

### 13.8. Визуальное направление и доступность

- Название продукта: **«Мои 3 дела»**, подзаголовок «Личный трекер задач без лишнего».
- Светлая спокойная тема, нейтральный фон, один индиго-акцент, системный шрифт, скруглённые карточки, аккуратные тени. Тёмная тема, PWA, офлайн-режим и синхронизация не входят в MVP.
- Приоритет: цвет + текст «Высокий»/«Средний»/«Низкий». Просрочка: текст «Просрочено на N дн.» + значок. Завершение: чекбокс + зачёркивание + «Завершено».
- Все интерактивные элементы доступны с клавиатуры, имеют видимый focus, подписи и доступные имена. Иконки-кнопки имеют `aria-label`.
- Диалоги: фокус внутри, Escape закрывает (с предупреждением о несохранённых изменениях), после закрытия фокус возвращается на инициатора. Ошибки полей связаны через `aria-describedby` и `aria-invalid`.
- Touch-target не меньше 44×44 px. На мобильном нет горизонтальной прокрутки. Брейкпоинты: mobile ≤ 767 px, tablet 768–1199 px, desktop ≥ 1200 px.
- Пустые состояния содержат короткое объяснение и полезное действие. Контраст текста — не ниже WCAG AA.

### 13.9. Дополнительные сценарии приёмки

К критериям раздела 11 добавляются проверки:

- [ ] Enter в быстром вводе создаёт задачу без срока, очищает поле и возвращает фокус.
- [ ] Пустое/пробельное название и название длиннее 200 символов не сохраняются; ошибка рядом с полем.
- [ ] Создание со сроком в прошлом запрещено; редактирование существующей задачи с прошедшим сроком разрешено.
- [ ] Нажатие на карточку не меняет статус; чекбокс меняет статус отдельно.
- [ ] При равных `dueDate`, приоритете и `createdAt` порядок детерминирован по `id`.
- [ ] Задача со сроком «вчера» остаётся просроченной при смене часового пояса; дата «сегодня» не сдвигается на вчера.
- [ ] После полуночи/возврата фокуса группы и счётчики пересчитываются.
- [ ] Две вкладки синхронизируют создание, редактирование, завершение и удаление.
- [ ] При одновременном открытии двух вкладок системное уведомление показывает только одна; переключение вкладок не повторяет его.
- [ ] Матрица уведомлений: первый запуск без запроса разрешения; включение из настроек; `granted`; `denied`; `unsupported`; выключенный тумблер; in-app fallback во всех случаях.
- [ ] Повреждённый `localStorage` не приводит к пустому списку; доступны повтор, сырой бэкап, импорт и сброс с подтверждением.
- [ ] Переполнение/недоступность хранилища показывает баннер, приложение остаётся работоспособным.
- [ ] Импорт: валидный файл, неверная версия, неверные типы, дубли UUID, несогласованный `completedAt`, отмена выбора, превышение 5 МБ — данные не меняются при ошибке.
- [ ] Экспорт → импорт возвращает тот же набор задач.
- [ ] Адаптивность проверена на 375, 768, 1024 и 1440 px; нет горизонтальной прокрутки.
- [ ] Клавиатурный проход по всем действиям; диалоги удерживают фокус и возвращают его; ошибки читаются скринридером.
- [ ] Lighthouse Accessibility/Best Practices без критичных замечаний; контраст и focus проверены вручную.

Системные уведомления проверяются в Chrome и Safari на `localhost`/HTTPS. Встроенный браузер OpenCode не используется как эталон: в текущем окружении у него `Notification.permission = denied`.
